# RÈGLES DEVIS --- C.I.D. Agencement

**Référentiel transversal --- Projet DEVIS**\
Version initiale : 01/10/2026\
Version publiée : 09/10/2026 — ruleset 2026.10.09.1

> Ce document regroupe les règles générales validées pour la préparation
> des devis C.I.D. Agencement.\
> Il doit être distingué des informations propres à un client ou à un
> chantier. En cas de règle particulière explicitement fixée dans un
> devis, cette règle particulière prévaut pour ce devis.

## 1. Organisation générale

-   Préparer les devis par **chapitres / zones / projets**, puis par
    **ouvrages**.
-   Un même devis peut contenir plusieurs projets ou zones distinctes ;
    conserver leur séparation pour permettre une lecture et un
    sous-total cohérents.
-   Chaque ouvrage peut contenir :
    -   une désignation ;
    -   une description client ;
    -   des articles / matériaux ;
    -   de la main-d'œuvre ;
    -   des consommables ;
    -   des informations de fournisseur et de prix ;
    -   des notes ou points à confirmer.
-   Conserver séparément :
    -   les informations relevées sur site ;
    -   les choix validés ;
    -   les hypothèses ;
    -   les points restant à vérifier.
-   Ne pas transformer une hypothèse ou une idée en élément acquis du
    devis sans validation.

## 2. Présentation des ouvrages

-   Présentation client privilégiée : **ouvrage + description**, sans
    exposer inutilement le détail interne du calcul.
-   Les composants restent disponibles dans les données de travail pour
    le chiffrage.
-   Les composants d'un ouvrage peuvent être libres et ne nécessitent
    pas tous une référence catalogue.
-   Un même ouvrage peut apparaître plusieurs fois dans un devis sous
    forme d'occurrences distinctes.
-   Les prix d'un devis préparé doivent pouvoir être **figés** afin
    qu'une évolution ultérieure du catalogue ne modifie pas
    rétroactivement le devis.

## 3. Main-d'œuvre

-   Utiliser le code **MO1** pour la main-d'œuvre principale.
-   Le nombre d'heures est défini ouvrage par ouvrage.
-   Le taux horaire de MO1 **n'est pas une constante universelle** :
    utiliser le taux explicitement défini pour le devis concerné.
-   Exemple déjà utilisé sur certains devis : **85 € HT/h**, mais ne pas
    l'appliquer automatiquement à tous les nouveaux devis sans
    confirmation ou règle active du dossier.

## 4. Marge et méthode de prix

-   La marge / le coefficient applicable doit être défini pour le devis
    ou la famille d'ouvrages concernée.
-   Ne pas appliquer automatiquement à tous les devis une marge utilisée
    sur un chantier particulier.
-   Une méthode historique de travail avec **multiplicateur ×3** existe
    pour certains chiffrages/prototypes ; elle ne doit être appliquée
    que lorsque le contexte du devis le prévoit.
-   Toujours conserver autant que possible le **prix d'achat HT**,
    l'origine du prix et sa date.

## 5. Fournisseurs et sourcing

### Priorité générale

Utiliser en priorité les **bases tarifaires professionnelles fournisseur
disponibles dans le projet**.

Fournisseurs régulièrement utilisés : - CEDEO ; - Point.P ; - Dispano
; - Foussier ; - Centre-Elec ; - Tollens ; - Normabaie, selon le type de
produit.

Les agences/fournisseurs précis peuvent dépendre du devis. Ne pas
transposer automatiquement l'agence choisie sur un chantier à tous les
autres.

### Recherche de prix

Ordre de recherche : 1. base fournisseur professionnelle active ; 2.
référence déjà validée dans un devis antérieur, en vérifiant qu'elle
reste adaptée ; 3. prix public Internet si aucune donnée professionnelle
exploitable n'est disponible.

Pour un prix Internet, conserver si possible : - la source ; - la date
; - la référence exacte ; - le lien produit.

### Références déjà validées

Avant de rechercher un nouveau produit, vérifier si une référence
appropriée a déjà été utilisée et validée dans les devis précédents.

## 6. Catalogues fournisseurs

-   Une seule version tarifaire active par fournisseur doit servir de
    référence courante dans les Sources du projet DEVIS.
-   Lorsqu'un nouveau fichier tarifaire est transmis :
    -   l'ajouter aux Sources du projet DEVIS ;
    -   remplacer/supprimer l'ancienne version active du même
        fournisseur.
-   Conserver pour les articles courants :
    -   fournisseur ;
    -   référence/code ;
    -   marque ;
    -   libellé ;
    -   unité ;
    -   dernier prix HT ;
    -   date/origine du prix.

## 7. Conditionnements --- règle obligatoire

Dès qu'un produit est vendu par : - colis ; - paquet ; - boîte ; -
panneau ; - rouleau ; - barre ; - cartouche ; - ou tout autre
conditionnement fixe,

calculer le **nombre entier de conditionnements nécessaires**, en
arrondissant au supérieur à partir du besoin net et du contenu réel du
conditionnement.

Conserver lorsque c'est utile : - besoin net chantier ; - nombre de
conditionnements achetés ; - quantité réellement achetée ; - reliquat.

## 8. Produits stockables et produits spécifiques

Distinguer deux cas.

### Produit standard, stockable et réutilisable

Exemples : - visserie ; - bande ; - colle standard ; - natte
d'étanchéité ; - rouleau générique ; - consommable courant.

Ne pas imputer automatiquement le conditionnement complet au chantier si
seule une partie est consommée.

Chiffrer : - la consommation réelle du chantier ; - éventuellement une
marge de pertes raisonnable.

Le reliquat est considéré comme **stock réutilisable**.

### Produit spécifique au chantier

Exemples : - parquet d'un décor précis ; - peinture teintée spécifique
; - élément réalisé ou commandé spécifiquement ; - produit difficilement
réutilisable.

Le conditionnement complet nécessaire peut être imputé au chantier
lorsque le reliquat n'a pas de valeur réaliste de réemploi.

## 9. Quantités, pertes et métrés

-   Toujours partir du **besoin net mesuré**.
-   Ajouter les pertes uniquement lorsqu'elles sont justifiées par le
    produit ou la pose.
-   Appliquer ensuite les règles de conditionnement.
-   Éviter les doubles comptages, notamment :
    -   faces de cloisons/murets ;
    -   retours déjà inclus dans un développé ;
    -   accessoires compris dans un kit ;
    -   surfaces communes à deux ouvrages.
-   Conserver les dimensions sources permettant de contrôler le métré.

## 10. Dépose et préparation

Lorsqu'une dépose est prévue, vérifier systématiquement si le devis doit
comprendre : - protection de la zone ; - dépose ; - manutention ; -
évacuation / traitement des déchets ; - préparation du support ; -
reprises après dépose.

Ne pas ajouter automatiquement ces prestations si elles n'ont pas été
validées, mais les signaler comme points de contrôle lorsqu'elles
peuvent être nécessaires.

## 11. Étanchéité et systèmes complets

Lorsqu'un ouvrage nécessite une étanchéité, raisonner en **système
complet**, et pas uniquement en produit surfacique.

Selon le cas, contrôler : - primaire ; - produit/membrane d'étanchéité
; - bandes d'angles ; - angles rentrants/sortants ; - raccords sol/mur
; - raccords autour des traversées ; - raccord au receveur ; -
accessoires prescrits par le fabricant.

## 12. Électricité et plomberie

-   Distinguer clairement :
    -   conservation des attentes/réseaux existants ;
    -   déplacement ;
    -   modification ;
    -   création complète.
-   Ne pas chiffrer une création complète lorsqu'un raccordement sur
    attente existante est prévu.
-   Pour une alimentation électrique existante réutilisée, préciser les
    adaptations réellement prévues : raccourcissement, sortie de câble,
    boîte, raccordement, etc.
-   Les contraintes techniques incertaines doivent rester identifiées
    comme **à vérifier** avant validation définitive.

## 13. Choix produits

Pour chaque produit restant à choisir : 1. définir les contraintes
dimensionnelles et techniques ; 2. chercher dans la base fournisseur
prioritaire ; 3. vérifier la fiche technique si nécessaire ; 4. proposer
une ou plusieurs références adaptées ; 5. faire valider le choix avant
de figer le devis lorsque le choix esthétique ou fonctionnel appartient
au client.

Ne pas choisir un produit uniquement parce qu'il rentre théoriquement
dans l'espace : prévoir les jeux de pose, dégagements et prescriptions
fabricant.

## 14. Workflow plateforme DEVIS

Workflow cible : 1. préparation du devis dans le chat client ; 2.
génération d'un JSON de travail ; 3. import dans la plateforme locale
d'échanges DEVIS ; 4. validation/modification/réponses ; 5. export JSON
des réponses ; 6. réintégration dans le chat ; 7. préparation pour
l'outil/module de devis final.

La plateforme est : - locale ; - autonome ; - hors ligne ; - générique
; - réutilisable pour tous les clients.

Les devis clients sont préparés dans leurs chats dédiés. Les règles
transversales appartiennent au présent référentiel.

## 15. Dolibarr / ERP Artisans

L'objectif final est l'intégration du processus de devis dans **Dolibarr
/ ERP Artisans**.

Principes déjà retenus : - privilégier les possibilités natives de
Dolibarr ; - étudier produits, services, kits et extrafields avant de
créer une logique spécifique ; - conserver une bibliothèque d'ouvrages
; - permettre des ouvrages utilisateur et des ouvrages issus de l'IA ; -
conserver les composants et calculs internes sans surcharger la
présentation client.

Les choix techniques d'intégration sont gérés dans le projet ERP
Artisans et ne doivent pas être inventés depuis ce fichier si le
référentiel GitHub contient une décision plus récente.

## 16. Contrôle avant finalisation d'un devis

Avant de considérer un chapitre ou un devis comme complet, contrôler au
minimum : - déposes ; - supports et préparations ; - fournitures
principales ; - accessoires de pose ; - consommables ; - étanchéité ; -
plomberie ; - électricité ; - finitions ; - peinture ; -
déchets/évacuation si concernés ; - conditionnements ; - pertes ; -
main-d'œuvre ; - références/prix/source/date ; - éléments conservés ; -
éléments explicitement hors prestation ; - points restant à confirmer.

## 17. Règle de maintenance du présent fichier

Ce fichier constitue le **référentiel des règles transversales DEVIS**.

Lorsqu'une nouvelle règle générale est validée : - l'ajouter ici ; -
éviter d'y inscrire les choix propres à un seul client ; - si une règle
remplace une ancienne règle, modifier la règle existante plutôt que
conserver deux instructions contradictoires ; - dater les évolutions
importantes si elles modifient la méthode de chiffrage.

Les données propres aux clients, métrés, produits choisis et décisions
de chantier doivent rester dans leurs dossiers/devis respectifs.

## 18. Workflow actuel plateforme DEVIS

Le workflow courant est organisé en trois modes :

1. **Mode 1 — Définition chantier** : reprendre les informations déjà connues, préparer les questions/confirmations conditionnelles nécessaires et éviter les allers-retours inutiles.
2. **Mode 2 — Produits spécifiques** : proposer uniquement les produits qui constituent un vrai choix client ou technique, conserver les refus et leurs motifs, permettre une précision libre pour l'IA et distinguer une recherche d'un autre produit d'une modification du besoin (`request_scope`).
3. **Mode 3 — Revue détaillée** : construire l'étude complète par sections, ouvrages et composants ; appliquer une revue par exception ; distinguer les contrôles à traiter maintenant de ceux à vérifier plus tard.

La sortie courante est un JSON `erp-artisans-quote-study` version `1.2`, exploitable par la plateforme, l'Assistant de devis autonome et, à terme, ERP Artisans.

Les décisions humaines prises dans les Modes 1 et 2 sont autoritaires : une révision IA peut signaler une incompatibilité ou créer un contrôle, mais ne doit pas les remplacer silencieusement.

## 19. Continuité entre choix produit et étude détaillée

- Tout besoin produit `supply_mode = cid` dont la décision est `retained` ou `retained_with_reservation` doit être matérialisé dans le Mode 3 comme **composant produit réel** du ou des ouvrages concernés.
- Le nom du produit dans le libellé d'un ouvrage ne suffit pas.
- Le composant conserve `selection_origin.product_need_id` et `selection_origin.candidate_id` lorsque le choix provient du Mode 2.
- Si un produit retenu manque dans l'étude détaillée, créer un contrôle à traiter avant finalisation.
- Les cas `supplied_by_client`, `existing_kept` et `excluded` sont des exceptions normales : ils influencent l'ouvrage sans créer automatiquement un achat C.I.D.

## 20. Autorité des décisions et retour IA

- Une décision humaine reste modifiable tant que le devis est en préparation, mais elle n'est jamais écrasée silencieusement.
- Lorsqu'un choix amont change, conserver l'ancien état dans l'historique et marquer les éléments dépendants à revoir plutôt que les supprimer automatiquement.
- Une demande « autre produit » conserve le besoin initial ; une demande « modifier le besoin » autorise l'IA à réexaminer les conséquences techniques et l'étude détaillée.
- Toute précision libre destinée à l'IA doit être conservée dans le JSON de travail et réutilisée au prochain échange.
